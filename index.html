RESEARCH QUESTION & EXPERIMENTAL SETUP

How effectively can historical and current-day air-pollution measurements predict next-day PM2.5 concentration and identify poor air-quality conditions?

This project investigates two supervised learning tasks using daily air-quality observations from Indian cities. The first task estimates the continuous PM2.5 concentration for the following day. The second converts the forecasting problem into a binary classification task by identifying whether next-day PM2.5 exceeds 90 µg/m³.

The experiments compare simple time-based forecasting baselines with machine-learning models. Evaluation is chronological: earlier observations are used for model development, a later period is used for validation and model selection, and the final held-out period is used for test evaluation.

01 — UNIT OF OBSERVATION

From city-day records to prediction samples

In the original city_day.csv dataset, one row represents the recorded air-quality measurements for one city on one date. For modelling, the data is organised as a city-specific daily time series. After feature engineering and target creation, one model-ready row represents one city and one prediction date, with features constructed from information available on that date and earlier dates.

02 — PREDICTION TIMING

Predicting one day ahead

The prediction is made using information available for the current day. The model uses the current PM2.5 measurement, historical PM2.5 lag features, rolling averages and selected measurements of other pollutants to estimate the PM2.5 concentration on the following day.

In temporal terms, features associated with date t are used to predict PM2.5 at date t + 1. The target is therefore shifted forward by one day rather than predicting the current day's concentration.

03 — TASK A: REGRESSION

Estimate next-day PM2.5 concentration

The regression target is the numerical PM2.5 measurement on the next day, expressed in µg/m³. The selected predictors include current PM2.5, PM2.5 lag features (1, 2, 3 and 7 days), rolling means over 3 and 7 days, and selected pollutant measurements: NO, NO2, NOx, NH3, CO, SO2, O3, Benzene and Toluene. City is also included as a categorical feature.

Persistence and a 7-day rolling-mean forecast provide reference baselines. These are compared with regression methods, with the final selected regression model being an RBF-kernel Support Vector Regressor (SVR).

04 — TASK B: CLASSIFICATION

Identify next-day poor air quality

The classification target is derived from next-day PM2.5. A sample is labelled 1 when next-day PM2.5 is greater than 90 µg/m³, and 0 otherwise. This converts the continuous concentration target into a binary prediction problem.

The classification experiments evaluate whether the model can identify days exceeding this threshold. The final selected classifier is Logistic Regression, using a probability threshold of 0.40 for the positive class.

05 — STUDY POPULATION

Pooled-city development and unseen-city evaluation

The pooled modelling dataset contains Bengaluru, Chennai, Delhi, Hyderabad, Lucknow and Patna. These cities provide the observations used for training, validation and the chronological test evaluation.

Mumbai and Guwahati are evaluated separately as unseen cities. This additional experiment examines how the selected regression model behaves on cities that were not part of the pooled model development dataset.

06 — TEMPORAL EVALUATION

Preserving chronological order

The model-ready pooled dataset contains 7,751 training observations, 2,188 validation observations and 1,098 test observations. Training targets cover 2 January 2015 to 31 December 2018; validation covers 2019; and the held-out test period covers 1 January 2020 to 1 July 2020.

The validation period is used for model comparison and selection. The test period is reserved for the final evaluation of the selected models. This chronological design reflects the intended forecasting setting, where future observations must not be used to develop a model for the past.

What the missingness pattern reveals

Missingness varies considerably across pollutant variables. Xylene has the highest missingness, with 7,261 missing observations (60.24%), followed by PM10 with 6,329 (52.51%) and NH3 with 3,859 (32.01%). In comparison, NO, NO2 and CO have substantially lower missingness.

PM2.5 has 957 missing observations (7.94%) in this prepared dataset. Since PM2.5 is the prediction target source, missing target values cannot be treated as ordinary missing predictor values. Samples without an available next-day PM2.5 target are excluded from supervised model evaluation rather than assigning artificial target values.

Missingness also influenced feature selection. Xylene and PM10 were excluded from the selected modelling predictors using a missingness threshold determined from training data. Other pollutant measurements, including NH3, were retained in the final feature set and handled during the preprocessing stage.

Why was Patna retained?

Five cities satisfied the 70% requirement in both periods. However, the project proceeded with a six-city pooled dataset. Patna was selected as the additional city because its training coverage (67.8%) was closest to the 70% cutoff among the remaining candidates, while its validation coverage was 99.7%.

Patna therefore represents an explicit exception to the initial screening criterion, rather than a city that passed it. This distinction is retained in the project documentation so that the selection decision remains transparent.

03 — EXPERIMENTAL DESIGN

From raw observations
to model evaluation.

The modelling workflow is designed around temporal prediction. Data from later dates are kept separate from model training and validation.

DATA PREPARATION & FEATURE ENGINEERING

Transforming daily observations into forecasting features

The original city-day observations were first restricted to the six selected cities. Each city's observations were organised on a daily date index so that temporal features could be constructed consistently. Missing dates introduced during daily reindexing were retained as missing observations rather than being treated as measured pollutant values.

1. Constructing the prediction target

The regression target was created by shifting PM2.5 forward by one day within each city. Thus, a feature record for city c on date t is associated with the PM2.5 observation for the same city on date t + 1. Records without an available next-day target were not eligible for supervised model training or evaluation.

2. Capturing recent pollution history

To represent temporal behaviour, the feature set includes PM2.5 lag values at 1, 2, 3 and 7 days. These features provide information about recent pollution levels at different time offsets.

Rolling means over 3 and 7 days were also constructed to represent recent average PM2.5 conditions rather than relying only on individual daily measurements. These features complement the current-day pollutant measurements and help represent short-term temporal patterns.

3. Selecting predictor variables

The selected numerical predictors include current PM2.5, its lag and rolling-mean features, and the pollutant measurements NO, NO2, NOx, NH3, CO, SO2, O3, Benzene and Toluene. City is included as a categorical predictor.

PM10 and Xylene were not included in the final selected feature set because of their substantial missingness. AQI and AQI_Bucket were excluded to avoid using these air-quality summary variables as predictors in the PM2.5 forecasting task.

4. Handling missing predictor values

Missing numerical predictor values were handled using median imputation. Median imputation provides a robust summary-based replacement and is less sensitive to extreme values than mean imputation. Missing target values were not imputed, because doing so would create artificial values for the quantity the models were expected to predict.

5. Scaling and categorical encoding

Numerical predictors were standardised using training-data statistics. City was transformed using one-hot encoding, with unseen categories handled through the configured unknown-category behaviour.

6. Preventing preprocessing leakage

The imputation and scaling transformations, along with categorical encoding, were fitted using the training data only. The fitted transformations were then applied to validation and test observations. This prevents information from the later evaluation periods from influencing preprocessing parameters during model development.

TEMPORAL VALIDATION STRATEGY

Training on the past, evaluating on the future

Since the objective is to predict next-day PM2.5, randomly distributing observations across training, validation and test sets would not represent the intended forecasting setting. The project therefore uses a chronological split based on Target_Date, preserving the temporal order of the prediction samples.

Exact split configuration

Dataset Target-date range Eligible observations Purpose
Training 02 Jan 2015 – 31 Dec 2018 7,751 Model fitting
Validation 01 Jan 2019 – 31 Dec 2019 2,188 Model comparison and selection
Test 01 Jan 2020 – 01 Jul 2020 1,098 Final evaluation

Role of each period

Training period: The training observations are used to fit the candidate models and the preprocessing transformations. This includes learning model parameters and estimating the numerical imputation and scaling statistics.

Validation period: The 2019 observations are used to compare candidate models and support model selection. This allows modelling decisions to be made without using the final test observations.

Test period: The observations from January to July 2020 are reserved for evaluating the selected models. They provide an estimate of performance on a later period that was not used for model selection.

Why preserve the test set?

Repeatedly using test results to choose models, features or hyperparameters would make the final evaluation less independent. Keeping the test period separate helps ensure that the reported test metrics reflect the performance of the selected approach on held-out future observations.

After next-day target creation and eligibility checks, the model-ready dataset contains 7,751 training, 2,188 validation and 1,098 test samples. These are the observation counts used in the subsequent modelling and evaluation experiments.

How the temporal features represent pollution history

The feature set combines the current day's pollutant measurements with historical PM2.5 information. This allows the models to use both the present pollution conditions and recent temporal behaviour when predicting the following day's concentration.

PM2.5 lag features

Lag features represent PM2.5 measurements from earlier dates within the same city:

  • Lag 1: PM2.5 from the previous day.
  • Lag 2: PM2.5 from two days earlier.
  • Lag 3: PM2.5 from three days earlier.
  • Lag 7: PM2.5 from seven days earlier.

These features provide the model with information about recent pollution levels at multiple time intervals instead of relying only on the current measurement.

Rolling-average features

The 3-day and 7-day rolling means summarise recent PM2.5 measurements over shorter and longer windows. They provide a smoothed representation of recent pollution conditions and complement the individual lag values.

Other pollutant measurements

The model also uses current-day measurements of NO, NO2, NOx, NH3, CO, SO2, O3, Benzene and Toluene. These variables provide additional information about the observed pollution conditions.

City as a categorical feature

City is included as a categorical variable and transformed using one-hot encoding. This allows the pooled model to distinguish observations belonging to different cities without treating city identifiers as continuous numerical values.

Feature availability and leakage prevention

All temporal predictors are constructed using information from the current date or earlier dates. The next-day PM2.5 value is reserved as the target and is not included among the predictors. AQI and AQI_Bucket are also excluded from the selected feature set.

Regression baselines and candidate models

Two simple baselines were used to determine whether machine learning models could improve next-day PM2.5 predictions. The persistence baseline predicts tomorrow's PM2.5 using today's value, while the 7-day mean baseline uses the average PM2.5 concentration over the previous seven days.

The candidate models included Ordinary Least Squares (OLS), Ridge Regression, Lasso Regression, Support Vector Regression (SVR) with an RBF kernel, Random Forest Regression, and Histogram-Based Gradient Boosting. These models allowed comparison between linear, regularized linear, and nonlinear approaches.

How the models were compared

Model selection was performed using the validation set. Mean Absolute Error (MAE) was the primary selection metric because it measures the average absolute prediction error in the original PM2.5 units. Root Mean Squared Error (RMSE) was also reported to show the influence of larger prediction errors.

SVR with an RBF kernel achieved the lowest validation MAE of 15.6688 µg/m³, compared with 16.3761 µg/m³ for the persistence baseline. This corresponds to approximately 4.32% lower MAE.

Random Forest was a close alternative, with a validation MAE of 15.8567 µg/m³ and a slightly lower RMSE than SVR. The final SVR configuration was selected based on its lower MAE. Its hyperparameters were C = 100, gamma = 0.01, and epsilon = 0.1.

The test set was kept separate from model selection and was not used to choose the model or tune its hyperparameters.

THRESHOLD 0.40

Classification baseline and model selection

The classification task identifies whether next-day PM2.5 exceeds 90 µg/m³. A positive label represents a day above this threshold, while a negative label represents a day at or below it.

Baseline comparison

A current-day threshold baseline was used as a simple reference. It applies the same 90 µg/m³ threshold to the current day's PM2.5 measurement to predict whether the following day will exceed the threshold. This provides a reference against which the classification models can be evaluated.

Choosing the classifier

Logistic Regression was selected because it achieved the highest validation Precision–Recall Area Under the Curve (PR-AUC), with a score of 0.9239515. PR-AUC evaluates the precision–recall relationship across different classification thresholds and is useful for assessing positive-class identification.

Choosing the operating threshold

The selected operating threshold was 0.40. Logistic Regression produces a probability for the positive class, and this threshold determines when a prediction is classified as positive. A lower threshold generally favours recall, while a higher threshold generally favours precision.

The threshold analysis illustrates this trade-off. The value 0.40 was used for the final selected classifier, while the held-out test set remained separate from validation-based model selection.

Test-set evaluation

After selecting Logistic Regression and fixing the operating threshold at 0.40 using validation data, the classifier was evaluated on the held-out test set. This set was not used during model selection.

Classification performance

The classifier achieved a test Precision of 0.7429, Recall of 0.8609, F1-score of 0.7975, PR-AUC of 0.8652, and Accuracy of 0.9399.

The recall indicates that the classifier identified a large proportion of the days that exceeded the 90 µg/m³ PM2.5 threshold. Its lower precision means that some predicted exceedance days did not correspond to actual exceedances.

Confusion matrix interpretation

On the test set, the classifier correctly identified 902 non-exceedance days and 130 exceedance days. It produced 45 false positives and 21 false negatives. These results show that the classifier detected most exceedance days, while still producing some false alarms.

Interpreting the prediction errors

The city-wise and monthly error breakdowns show that overall test metrics do not represent performance uniformly across locations and dates. The largest prediction errors were concentrated particularly in January 2020, with Delhi, Lucknow and Patna appearing among the cities with notable deviations.

Pre-lockdown and lockdown comparison

The test period was divided into pre-lockdown and lockdown periods using 25 March 2020 as the boundary. During the pre-lockdown period, SVR achieved an MAE of 15.68 µg/m³, compared with 16.09 µg/m³ for the persistence baseline. During the lockdown period, the corresponding MAE values were 7.87 µg/m³ for SVR and 7.85 µg/m³ for persistence.

The comparison shows that SVR's improvement over persistence was not uniform across the two periods. Its MAE was slightly lower than persistence before the lockdown, while the two methods had nearly identical MAE during the lockdown period.

These period-wise differences are descriptive observations from the test data. They do not establish that lockdown conditions caused changes in model performance.

Why this analysis matters

Examining errors by city, month and period helps identify where the model's predictions are less reliable. It also highlights why model evaluation should consider the distribution of errors and not rely only on a single aggregate metric.

10 — LIMITATIONS

What the results
do not establish.

A responsible interpretation requires acknowledging the boundaries of the dataset, experimental design and selected models.

01

Missing observations

Several pollutant variables contain substantial missingness, which affects feature availability and city coverage.

02

Limited test horizon

The pooled test period ends on 1 July 2020 and does not cover the later crop-burning season.

03

City generalisation

Results on unseen cities are mixed and do not establish uniform transferability across India.

04

Prediction, not causation

Statistical relationships in the model should not be treated as evidence of causal effects between pollutants.

05

Coverage differences

Patna was retained despite not passing the initial 70% city-coverage screening threshold.

06

Historical conditions

The evaluation reflects the observed historical period and should not be assumed to represent present-day air quality.

Limitations in the context of the experimental results

1. Modest regression improvement

On the pooled test set, SVR achieved an MAE of 11.46 µg/m³, compared with 11.63 µg/m³ for the persistence baseline. Although SVR performed better, the improvement was approximately 1.52%. This indicates that the selected machine-learning model provides only a modest improvement over a simple time-based forecast.

2. Classification threshold trade-off

The classifier achieved a test recall of 0.8609 and precision of 0.7429 at the selected probability threshold of 0.40. While it identified most threshold-exceedance days, some predicted exceedances were false alarms. Different operating thresholds could produce different precision and recall values.

3. Generalisation to unseen cities

The separate evaluation on Mumbai and Guwahati provides evidence about performance beyond the pooled development cities. However, only two unseen cities were examined, so these results are not sufficient to establish generalisation across all Indian cities.

4. Limited predictor information

The selected predictors primarily describe pollutant measurements and their recent temporal patterns. The experiments do not incorporate additional meteorological information such as wind speed, temperature or rainfall, which could provide further context about atmospheric conditions.

5. Historical evaluation period

The held-out test period covers January to July 2020. Performance during this period may not represent other seasons or more recent pollution patterns. Evaluation on additional years and seasonal conditions would be needed to assess longer-term reliability.

11 — CONCLUSION

A measured approach to
air-quality prediction.

This project evaluates next-day PM2.5 regression and poor-air-quality classification through a chronological machine-learning workflow. Its results highlight the importance of baseline comparisons, temporal validation, error analysis and testing generalisation beyond the development cities.

What the experimental results tell us

The final SVR model achieved a test MAE of 11.46 µg/m³, compared with 11.63 µg/m³ for the persistence baseline. This represents a modest improvement, showing that recent pollutant measurements and temporal features provide some additional predictive value, but do not substantially outperform a simple time-based forecast.

For classification, Logistic Regression achieved a test recall of 0.8609 at the selected probability threshold of 0.40. This indicates that the model identified most of the next-day high-PM2.5 events, although its precision of 0.7429 shows that some predicted events were false alarms.

Evaluation on Mumbai and Guwahati showed that performance can vary across cities. Therefore, results from the six development cities should not be assumed to transfer uniformly to other locations.

Overall, the project demonstrates a chronological machine-learning workflow for next-day PM2.5 prediction and high-pollution-day classification. The findings also highlight why comparisons with simple baselines, careful validation and transparent reporting of limitations are essential.

Experiment reproduction workflow

1. Obtain the dataset

Download the original city-day air-quality dataset and place the CSV file in the location expected by the data-loading notebook. The raw dataset is not modified directly.

2. Run the notebooks in sequence

Begin with data understanding and quality assessment, followed by preprocessing, feature engineering and baseline construction. Continue with model training and validation, then perform final test evaluation and error analysis.

3. Maintain chronological evaluation

Use the same chronological split as the reported experiments: training from 2 January 2015 to 31 December 2018, validation throughout 2019, and testing from 1 January to 1 July 2020. Do not use the test set for model selection or hyperparameter tuning.

4. Reproduce the final models

The final regression model is an RBF-kernel Support Vector Regressor with C = 100, gamma = 0.01 and epsilon = 0.1. The final classification model is Logistic Regression with a probability threshold of 0.40.

5. Generate and inspect the outputs

Save the prepared datasets, evaluation metrics, prediction files, plots and experiment summaries. Compare the reproduced results with the reported website results while accounting for any differences in software versions or execution environments.
